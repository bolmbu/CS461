# คู่มือการทำงานและฟังก์ชัน CoopReady AI

เว็บแอปเตรียมความพร้อมสหกิจศึกษา

ฉบับอธิบายระบบ v1.4.3   •   1 พฤศจิกายน 2569

คู่มือนี้ใช้สำหรับเปิดใช้งาน ส่งต่อโครงงาน และอธิบายการทำงานตอนนำเสนอ โดยครอบคลุมหน้าเว็บ กระบวนการประมวลผล โมเดล ฐานข้อมูล API และฟังก์ชันหลักในโค้ด

ระบบช่วยตรวจหลักฐานทักษะจาก Resume เทียบกับ Role Brief หรือ JD ฝึกสัมภาษณ์ และตอบคำถามสหกิจจากฐานความรู้ที่มีแหล่งอ้างอิง ผู้ใช้เริ่มทดลองด้วย Baseline ได้ก่อน แล้วจึงติดตั้งโมเดลเพิ่มเติมเพื่อใช้ Proposed และเสียง

### ขอบเขตของระบบปัจจุบัน

- เป็นต้นแบบที่รันบนเครื่องผู้ใช้ด้วย Next.js และ FastAPI เก็บข้อมูลใน SQLite

- ใช้โมเดลที่ฝึกมาแล้วเพื่อประมวลผล ไม่ได้ฝึก Qwen3 หรือ MiniLM ใหม่จากชุด Resume ของโครงงาน

- เสียงเป็นการถามและตอบทีละรอบ ต้องหยุดอัดก่อนถอดเสียง ยังไม่ใช่การสนทนาเสียงแบบสตรีมพร้อมขัดจังหวะ

- ไม่มีระบบส่งใบสมัครจริง ระบบล็อกอิน หรือ Workflow อนุมัติคำร้องของอาจารย์

### แผนการอ่าน

| ต้องการทำอะไร | อ่านหัวข้อ |
| --- | --- |
| เปิดใช้ครั้งแรก | 1 และ 2 |
| ใช้งานทุกหน้าของเว็บ | 3 ถึง 8 |
| เข้าใจ AI ข้อมูลและผลประเมิน | 9 ถึง 11 |
| แก้ปัญหาและส่งต่อเครื่องอื่น | 12 |

เลขเวอร์ชันหน้าตาเว็บเป็น 1.4.3 ส่วน API ยังคงระบุ 1.4.1 เพราะการปรับล่าสุดเป็นส่วนติดต่อผู้ใช้ ไม่ได้เปลี่ยนสัญญา API

## 1 การเปิดใช้ใน VS Code

### สิ่งที่ต้องมี

- Python 3.11 หรือ 3.12 และ Node.js 22 ขึ้นไป โดยเรียกคำสั่งจาก Terminal ได้

- แตกไฟล์โครงงานทั้งโฟลเดอร์ แล้วเปิดโฟลเดอร์ที่มี launch.py ใน VS Code

- มีอินเทอร์เน็ตสำหรับติดตั้งแพ็กเกจครั้งแรก และดาวน์โหลดโมเดลเมื่อต้องใช้ AI

### เริ่มระบบ

```text
python launch.py
```

คำสั่งนี้ตรวจ Python และ Node สร้าง backend/.venv ติดตั้งแพ็กเกจ Python และ frontend เมื่อจำเป็น สร้างไฟล์ตั้งค่าจากตัวอย่างถ้ายังไม่มี แล้วเปิด Backend กับเว็บไซต์ให้ใน Terminal เดียว

รอข้อความพร้อมใช้งานและเปิด URL เว็บไซต์ที่แสดงใน Terminal ปกติใช้ http://127.0.0.1:3000 ส่วน http://127.0.0.1:8001/docs เป็นหน้า API หากพอร์ตไม่ว่าง ตัวเปิดจะหาพอร์ตอื่นให้ จึงควรยึด URL ที่แสดงจริง

บน Windows ถ้าไม่พบคำสั่ง python แต่มี Python Launcher ให้ใช้ py -3.12 launch.py แทน ห้ามปิด Terminal ขณะใช้งาน กด Ctrl+C เมื่อต้องการหยุดทั้งสองส่วน

| คำสั่ง | หน้าที่ |
| --- | --- |
| python launch.py --doctor | ตรวจสภาพแวดล้อมและการตั้งค่า ไม่ติดตั้งโมเดล |
| python launch.py --setup-only | ติดตั้งส่วนพื้นฐานแล้วจบ ไม่เปิดเว็บ |
| python launch.py --repair | ซ่อมสภาพแวดล้อมและแคชที่สร้างอัตโนมัติ |
| python launch.py --no-browser | เปิดเซิร์ฟเวอร์โดยไม่เปิดเบราว์เซอร์อัตโนมัติ |

### เริ่มทดลองอย่างง่าย

เลือก Baseline สร้างรายการใหม่ กรอกข้อมูลหรือใช้ตัวอย่างสมมติ บันทึก แล้ววิเคราะห์ Resume หรือเริ่มสัมภาษณ์ด้วยการพิมพ์ได้ทันที ยังไม่จำเป็นต้องมี Ollama, MiniLM, Whisper หรือ Piper สำหรับเส้นทางนี้

ข้อมูลตัวอย่างมีไว้ตรวจการทำงาน ไม่ใช่ระเบียบมหาวิทยาลัยหรือผลประเมินนักศึกษาจริง

## 2 ส่วนประกอบและการไหลของข้อมูล

| ส่วน | หน้าที่ในโครงงาน |
| --- | --- |
| Next.js และ React | แสดงหน้าเว็บ รับไฟล์ คำตอบ และเสียงจากเบราว์เซอร์ |
| เส้นทาง /backend | รับคำขอจากหน้าเว็บ แล้วส่งต่อไป FastAPI รวมถึงไฟล์และเสียง |
| FastAPI และ Pydantic | ตรวจข้อมูล เรียกอัลกอริทึมและโมเดล ควบคุมรอบสัมภาษณ์ |
| SQLite | เก็บ Session, FAQ และประวัติคำถาม FAQ |
| Ollama กับ Qwen3 | ให้โมเดลภาษาเขียนสรุป คำถาม คำตอบ FAQ และรายงาน |
| MiniLM กับ Chroma | แปลงข้อความเป็นเวกเตอร์ และค้นข้อมูลที่ใกล้เคียง |
| faster-whisper และ Piper | ถอดเสียงเป็นข้อความ และสร้างเสียงอ่านคำถาม |

### ลำดับการทำงานโดยรวม

1. ผู้ใช้นำเข้า Resume และกรอกบริษัท ตำแหน่ง และ Role Brief ระบบแยกข้อความให้ตรวจแก้ก่อนบันทึก Session

2. ผู้ใช้เพิ่มข้อมูลบริษัทจาก URL หรือข้อความที่คัดลอกมา จากนั้นเลือกตรวจทักษะหรือเริ่มสัมภาษณ์ได้ ข้อมูลบริษัทเป็นบริบทเสริม ไม่จำเป็นสำหรับ Baseline

3. ระบบสร้างคำถามตามโหมด ผู้ใช้พิมพ์หรืออัดเสียง เมื่อส่งคำตอบ ระบบบันทึกและเตรียมคำถามถัดไปจนจบรอบ

4. ระบบสร้างรายงาน เก็บประวัติ และส่งออก JSON ได้ ส่วน FAQ ทำงานเป็นเส้นทางแยก โดยค้นจากรายการความรู้ที่นำเข้าและผ่านเงื่อนไขการใช้งาน

### สิ่งที่ทำงานในเครื่องและสิ่งที่ใช้อินเทอร์เน็ต

การวิเคราะห์และสร้างคำตอบผ่าน Ollama ที่ตั้งค่าเป็น 127.0.0.1 ทำงานกับโมเดลในเครื่อง ส่วนการค้น DDGS การอ่านเว็บไซต์ และการดาวน์โหลดแพ็กเกจหรือโมเดลใช้อินเทอร์เน็ต โค้ดฉบับนี้ไม่ได้เชื่อม OpenAI Cloud API

Browser TTS เป็นเสียงสำรองของเบราว์เซอร์หรือระบบปฏิบัติการ เส้นทางประมวลผลขึ้นกับเสียงที่เลือก จึงไม่ควรอ้างว่าเสียงสำรองทั้งหมดประมวลผลในเครื่องเสมอ

## 3 โหมดพื้นฐานและโหมด AI

| งาน | Baseline | Proposed |
| --- | --- | --- |
| จับทักษะ | พจนานุกรมและคำที่พบ | เพิ่ม MiniLM หาหลักฐานที่มีความหมายใกล้กัน |
| ความคล้าย Resume กับ JD | TF-IDF และ cosine | ยังมี TF-IDF พร้อมผลเชิงความหมายแยกต่างหาก |
| คำถามสัมภาษณ์ | 5 คำถามตามหัวข้อคงที่ | Qwen3 สร้าง 5 คำถามหลัก และ 2 คำถามต่อยอด |
| คำถามต่อยอด | ไม่มี | หลังคำถามหลักข้อ 1 และ 2 โดยอ้างคำตอบล่าสุด |
| รายงาน | รายการให้ผู้ประเมินตรวจ ไม่มีคะแนนอัตโนมัติ | Qwen3 ให้คะแนน 5 มิติพร้อมหลักฐาน |
| FAQ | ค้น TF-IDF และใช้คำตอบรายการอันดับแรก | MiniLM กับ Chroma ค้นข้อมูล แล้ว Qwen3 เรียบเรียงคำตอบ |
| สรุปบริษัทด้วย Qwen3 | ไม่เปิดใช้ | ผู้ใช้เลือกเปิดได้ |

### เหตุผลที่มีคำถามคงที่

Baseline เป็นจุดตั้งต้นที่ตรวจซ้ำและเปรียบเทียบได้ มีหัวข้อแนะนำตัว โครงงาน ปัญหายาก การทำงานร่วมกับผู้อื่น และเป้าหมายเรียนรู้ แม้คำถามแรกใส่ชื่อตำแหน่ง แต่ไม่ได้สร้างคำถามใหม่ด้วย LLM

Proposed ใช้ Resume, Role Brief, ข้อมูลบริษัท และประวัติคำตอบเป็นบริบท จึงปรับเนื้อหาคำถามได้ อย่างไรก็ตาม จุดที่แทรกคำถามต่อยอดถูกกำหนดไว้สองครั้ง ไม่ใช่ระบบที่ตัดสินใจได้อิสระว่าจะถามต่อทุกช่วง

### ติดตั้งความสามารถเพิ่ม

```text
ollama pull qwen3:4b
python launch.py --install-ai semantic --prepare-models semantic
python launch.py --install-ai stt --prepare-models stt
python launch.py --install-ai tts
```

ต้องติดตั้งและเปิด Ollama ก่อนใช้คำสั่ง pull ส่วน Piper ต้องจัดหาไฟล์เสียง .onnx และ .onnx.json ที่ตรงภาษาเอง การติดตั้งแพ็กเกจ tts อย่างเดียวไม่ทำให้มีเสียงพร้อมใช้

หน้าแสดงสถานะตรวจว่าพบแพ็กเกจหรือไฟล์หรือไม่ การแสดงว่าพร้อมไม่ได้ยืนยันว่ารันโมเดลจริงบนเครื่องนั้นสำเร็จแล้ว

## 4 หน้าเตรียมข้อมูลและตรวจ Resume

### สร้างและจัดการรายการ

กรอกบริษัท ตำแหน่ง Resume และ Role Brief หรือ JD เลือกภาษาไทยหรืออังกฤษ แล้วให้ความยินยอมจัดเก็บข้อมูลในเครื่องก่อนบันทึก ระบบสร้าง Session ID เพื่อเชื่อมข้อมูลบริษัท ผลวิเคราะห์ และการสัมภาษณ์ไว้ด้วยกัน

เมื่อบันทึกแล้ว ระบบใช้ข้อมูลของ Session นั้น ช่องข้อมูลหลักจะถูกล็อก หากต้องเปลี่ยน Resume หรือบทบาทให้สร้างรายการใหม่ สามารถเริ่มร่างโดยเก็บข้อความเดิมได้ แต่ต้องยืนยันความยินยอมอีกครั้ง

### นำเข้าไฟล์

| ชนิด | วิธีอ่านและข้อจำกัด |
| --- | --- |
| PDF ข้อความ | pypdf อ่านได้ไม่เกิน 50 หน้า ไม่มี OCR สำหรับ PDF สแกน |
| DOCX | อ่านย่อหน้าและข้อความในตาราง จำกัดขนาด ZIP หลังคลายไม่เกิน 30 MB |
| TXT | อ่าน UTF-8 รวมไฟล์ที่มี BOM |

ขนาดไฟล์นำเข้าสูงสุด 10,000,000 ไบต์ ข้อความที่ส่งกลับตัดไว้ไม่เกิน 60,000 ตัวอักษร พร้อมแจ้งหากถูกตัด ระบบเก็บข้อความที่บันทึกใน Session ไม่ได้เก็บไฟล์ Resume ต้นฉบับ

ตรวจลำดับการอ่านเสมอ โดยเฉพาะ Resume หลายคอลัมน์ หาก PDF ไม่มีข้อความให้คัดลอกข้อความเอง หรือแปลงด้วย OCR ภายนอกก่อน ข้อความที่สกัดผิดย่อมทำให้ AI ตีความผิดได้

### อ่านผลวิเคราะห์

- Matched คือพบคำหรือหลักฐานที่เกี่ยวข้องกับทักษะที่ต้องการ ไม่ใช่การรับรองความเชี่ยวชาญ

- Not Evidenced คือยังไม่พบหลักฐานจากข้อความ ไม่ได้ยืนยันว่าผู้ใช้ไม่มีทักษะนั้น

- คำแนะนำชวนให้เพิ่มหน้าที่ วิธีทำ และผลลัพธ์ที่ทำจริง ไม่ควรใส่ทักษะที่ยังไม่เคยทำ

- ค่าความคล้ายเป็นคะแนนเปรียบเทียบข้อความ ไม่ใช่ Accuracy หรือเปอร์เซ็นต์โอกาสได้งาน

หากไม่มีรายการทักษะ อาจเป็นเพราะ JD ไม่กล่าวถึงคำในพจนานุกรม ไม่ควรสรุปว่า Resume ตรงทุกข้อ สามารถขยายรายการคำและชื่อเรียกใน backend/app/baseline.py ได้

## 5 ข้อมูลบริษัทและการค้น DDGS

### สองวิธีเพิ่มแหล่งข้อมูล

วิธีแรกใส่ Official URL แบบ HTTPS แล้วกดบันทึกหรืออ่าน Profile วิธีที่สองคัดลอกข้อความจริงจากหน้าเกี่ยวกับบริษัทหรือผลิตภัณฑ์มาวางในช่องข้อความ วิธีวางข้อความเหมาะเมื่อเว็บใช้ JavaScript หรืออ่านอัตโนมัติไม่ได้ และจะถูกใช้ก่อน URL ถ้ามีข้อความอยู่แล้ว

เมื่ออ่านจาก URL ระบบจะตั้งสถานะผู้ใช้ตรวจแหล่งข้อมูลเป็นยังไม่ยืนยัน เพราะเพิ่งดึงเนื้อหามา ผู้ใช้ต้องตรวจข้อความก่อน แล้วบันทึกข้อความที่ตรวจแล้วพร้อมเครื่องหมายยืนยันอีกครั้ง การเปลี่ยน URL ล้างข้อมูลแหล่งเดิมเพื่อไม่ให้ปะปน

### ปุ่มค้นแหล่งข้อมูลด้วย DDGS

DDGS ช่วยค้นรายการที่เป็นไปได้ URL ของบริษัท เมื่อได้ผลให้เปิดตรวจเองแล้วเลือกเว็บไซต์ทางการ ผลค้นไม่กลายเป็นข้อเท็จจริงที่ยืนยันแล้วโดยอัตโนมัติ ถ้าค้นไม่สำเร็จยังใช้ Official URL หรือวางข้อความเองได้

DDGS ไม่ใช่ตัวสร้างคำตอบ AI และไม่จำเป็นต่อการฝึกสัมภาษณ์พื้นฐาน การค้นอาจว่าง ถูกจำกัดคำขอ หรือเครือข่ายเชื่อมต่อไม่ได้

### ให้ Qwen3 สรุปพร้อมหลักฐาน

เลือก Proposed และเปิด Ollama ก่อนจึงเลือกตัวช่วยสรุปได้ Backend แบ่งข้อความบริษัทเป็นช่วง ให้โมเดลคืนข้อเท็จจริงพร้อมหมายเลขช่วงต้นทาง แล้วระบบแนบข้อความจากช่วงนั้นเป็นหลักฐานโดยตรง

สรุปได้ไม่เกิน 8 ข้อ และแสดงข้อมูลที่ยังขาด ระบบตรวจรูปแบบ JSON และหมายเลขแหล่งอ้างอิง หากตรวจไม่ผ่านจะเก็บข้อความต้นทางไว้และแจ้งสรุปไม่สำเร็จ ไม่สร้างสรุปสมมติแทน

การมีข้อความอ้างอิงยังไม่พิสูจน์ว่าข้อสรุปถูกต้องทั้งหมด ผู้ใช้ต้องอ่านเทียบความหมาย โดยเฉพาะคำกล่าวที่กว้างกว่าต้นฉบับ ข้อมูลส่วนนี้ใช้ธุรกิจและผลิตภัณฑ์เป็นบริบท ไม่ใช่ค้นตำแหน่งเปิดรับหรือส่งใบสมัคร

### ข้อจำกัดการอ่านเว็บ

รับ HTTPS สาธารณะ ไม่รับบัญชีหรือรหัสผ่านใน URL และบล็อกปลายทางภายในเครื่อง ตรวจปลายทางซ้ำเมื่อเปลี่ยนเส้นทาง อ่านเฉพาะ HTML ไม่เกิน 2 MB และไม่รัน JavaScript ถ้าเว็บไม่รองรับให้ใช้การวางข้อความ

## 6 ฝึกสัมภาษณ์และใช้เสียง

### ลำดับการฝึก

1. เปิด Session แล้วเลือกโหมดก่อนเริ่ม ระบบแสดงคำถามปัจจุบันครั้งละข้อ เมื่อเริ่มแล้วโหมดถูกล็อกไว้ระหว่างสัมภาษณ์

2. พิมพ์คำตอบ หรือกดเริ่มพูด อนุญาตไมโครโฟน จากนั้นกดหยุดและถอดเสียง รอข้อความปรากฏ แล้วแก้คำที่ถอดผิดได้ก่อนยืนยันส่ง

3. กดยืนยันและส่งคำตอบ ระบบบันทึกคำตอบและแสดงคำถามต่อไป หากเป็นคำถามต่อยอดจะแสดงข้อความที่อ้างจากคำตอบก่อนหน้า

4. จบครบคำถาม หรือจบก่อนหลังตอบอย่างน้อยหนึ่งข้อ แล้วเปิดรายงาน เริ่มสัมภาษณ์ใหม่ใน Session เดิมจะแทนที่การสัมภาษณ์เดิม จึงควรส่งออกรายงานที่ต้องการเก็บก่อน

### ถอดเสียงกับอ่านเสียงเป็นคนละส่วน

| ส่วน | รับและส่งข้อมูล | ข้อกำหนด |
| --- | --- | --- |
| STT | เสียงผู้ใช้ → ข้อความคำตอบ | faster-whisper และโมเดล Whisper |
| TTS หลัก | ข้อความคำถาม → เสียง WAV | Piper พร้อมไฟล์เสียงตรงภาษา |
| TTS สำรอง | ข้อความคำถาม → เสียงเบราว์เซอร์ | เปิดเลือก Browser TTS เอง |

เครื่องบันทึกใช้ MediaRecorder บน localhost หรือบริบทปลอดภัย เลือกชนิดเสียงที่เบราว์เซอร์รองรับ จำกัด 3 นาทีต่อครั้ง และไฟล์ไม่เกิน 15 MB ระหว่างบันทึกจะหยุดเสียงอ่านคำถาม เพื่อไม่ให้อัดเสียงของระบบติดไปด้วย

Backend ส่งไฟล์ชั่วคราวให้ faster-whisper แล้วลบทิ้งหลังจบคำขอ เก็บคำตอบเป็นข้อความใน Session ไม่เก็บเสียงต้นฉบับระยะยาว หากถอดไม่ได้สามารถพิมพ์คำตอบต่อได้

### เวลาและตัวนับ

STT ms คือเวลาถอดเสียงรวมการโหลดครั้งแรกเมื่อจำเป็น TTS ms คือเวลาสร้างเสียง Piper ส่วน LLM ms คือเวลาเรียกโมเดล ไม่ใช่เวลาพูดของผู้ใช้ Browser TTS ตั้ง TTS ms เป็น 0 จึงไม่ถูกนับเป็นรอบเสียง local ที่ใช้ทั้ง Whisper และ Piper

ระบบยังไม่แสดงข้อความถอดสด ไม่ตรวจจบประโยคเพื่อส่งอัตโนมัติ และไม่รับการพูดแทรกแบบผู้ช่วยเสียงเรียลไทม์

## 7 Chatbot สหกิจและฐานความรู้

### ข้อมูลที่ใช้ตอบ

FAQ มีคำถาม คำตอบ ชื่อแหล่งอ้างอิง หน้า รุ่นเอกสาร วันหมดอายุ และสถานะอนุมัติ ผู้ดูแลนำเข้าเป็น JSON ผ่านส่วนจัดการข้อมูลในหน้า FAQ ปัจจุบันยังไม่มีตัวอ่านประกาศ PDF แล้วแปลงเป็น FAQ อัตโนมัติ

รายการที่จะใช้ตอบจริงต้อง approved เป็น true และไม่หมดอายุ ส่วนข้อมูล demo จะถูกใช้ก็ต่อเมื่อผู้ใช้เปิดอนุญาตข้อมูลสมมติ หน้าเว็บแสดงแหล่งอ้างอิงให้ตรวจประกาศฉบับจริงต่อได้

### ตัวอย่างรูปแบบหนึ่งรายการ

```text
[{
  "question": "ต้องส่งเอกสารที่ไหน",
  "answer": "ข้อความที่ตรวจจากประกาศจริง",
  "source": "ชื่อประกาศที่ใช้จริง",
  "page": "2", "version": "รุ่นประกาศ",
  "valid_until": null, "approved": false, "demo": false
}]
```

ตัวอย่างนี้เป็นแบบฟอร์ม ไม่ใช่คำตอบจริง เปลี่ยนเนื้อหา ตรวจแหล่งอ้างอิง แล้วจึงอนุมัติรับเข้าฐานความรู้ แต่ละครั้งที่นำเข้าจะสร้างรายการใหม่ ระบบไม่รวมรายการซ้ำให้โดยอัตโนมัติ

### ขั้นตอนตอบแต่ละโหมด

Baseline ค้นความคล้ายระหว่างคำถามผู้ใช้กับคำถามใน FAQ ด้วย TF-IDF ถ้าคะแนนสูงสุดผ่านเกณฑ์เริ่มต้น 0.17 จะใช้คำตอบรายการนั้น ถ้าไม่ผ่านจะตอบว่าไม่มีข้อมูลที่ยืนยัน

Proposed แปลงคำถามเป็นเวกเตอร์ ค้น Chroma ไม่เกิน 3 รายการที่ผ่านเกณฑ์เริ่มต้น 0.55 แล้วส่งให้ Qwen3 เรียบเรียงคำตอบ ตรวจว่าอ้างเฉพาะ ID ของรายการที่ค้นได้ โมเดลสามารถงดตอบเมื่อข้อมูลไม่พอ

เกณฑ์ดังกล่าวเป็นค่าตั้งต้น ยังไม่ใช่เกณฑ์ที่พิสูจน์ความแม่นยำกับประกาศของหลักสูตร Citation ที่ถูก ID ไม่รับประกันว่าทุกประโยคสอดคล้องต้นฉบับ ต้องประเมินความถูกต้องกับผู้รับผิดชอบเอกสาร

### เมื่อไม่มีคำตอบ

ระบบควรแจ้งว่าไม่มีข้อมูลที่ยืนยันและให้ติดต่อผู้ประสานงาน ไม่ควรแต่งวันกำหนดส่งหรือข้อบังคับขึ้นเอง ควรเพิ่มประกาศที่ตรวจแล้วและทดสอบคำถามทั้งที่มีและไม่มีคำตอบในฐานความรู้

## 8 ประวัติ รายงาน และเครื่องมือประเมิน

### ภาพรวมและประวัติ

หน้าแรกแสดงรายการล่าสุดและทางลัด ส่วนหน้าผลการทดลองเปิด Session เดิม ดูรายงาน ลบรายการ และส่งออกข้อมูลได้ ประวัติรายการไม่ใช่ Dashboard ติดตามการยื่นสมัครจริง เพราะระบบยังไม่เก็บขั้นตอนส่งใบสมัคร นัดสัมภาษณ์ หรือผลรับเข้าของบริษัท

### รายงานสัมภาษณ์

| มิติ | สิ่งที่ใช้พิจารณา |
| --- | --- |
| ความตรงคำถาม | คำตอบตอบประเด็นที่ถามหรือไม่ |
| หลักฐานจากประสบการณ์ | มีเหตุการณ์ หน้าที่ และผลงานที่อธิบายได้หรือไม่ |
| เหตุผลและขั้นตอน | อธิบายกระบวนการคิดและการแก้ปัญหาได้หรือไม่ |
| ความชัดเจนในการสื่อสาร | เรียงเนื้อหาจากข้อความคำตอบได้ชัดหรือไม่ |
| การเชื่อมกับบทบาทงาน | เชื่อมประสบการณ์กับ Role Brief ได้หรือไม่ |

Baseline ให้ผู้ประเมินตรวจตามมิติเหล่านี้ ค่า score เป็นว่าง ส่วน Proposed ให้คะแนนจำนวนเต็ม 1 ถึง 5 พร้อมคำอ้างจากคำตอบ ข้อเสนอแนะ และสิ่งที่ควรปรับปรุง ระบบไม่ประเมินบุคลิก ความมั่นใจจากน้ำเสียง หรือความเหมาะสมในการจ้างงาน

รายงานสร้างได้เมื่อจบรอบและมีอย่างน้อยหนึ่งคำตอบ ถ้าเคยสร้างแล้วจะคืนรายงานเดิมเพื่อไม่เรียกโมเดลซ้ำโดยไม่จำเป็น ระยะเวลารวมวัดจากเริ่มจนจบรอบ จึงรวมเวลาที่ผู้ใช้หยุดคิดด้วย

### วัดการถอดเสียง

ใส่ข้อความอ้างอิงที่คนตรวจแล้ว และข้อความที่ STT ถอดได้ จากนั้นคำนวณ CER และ WER ค่า 0 หมายถึงตรงกันหลังปรับรูปแบบ ค่าอาจเกิน 1 ได้เมื่อมีการเพิ่มข้อความมาก ไม่ใช่คะแนนความแม่นยำแบบเปอร์เซ็นต์

CER ใช้ระยะห่างการแก้ไขระดับตัวอักษรหารจำนวนตัวอักษรอ้างอิง โดยลบช่องว่างก่อน ส่วน WER ในระบบแบ่งคำด้วยช่องว่าง จึงไม่ใช่การตัดคำไทย ควรใช้ CER เป็นตัวหลักสำหรับภาษาไทย

### วัดการจับคู่ทักษะ

กรอก Ground truth ที่คนตรวจแล้วเทียบกับทักษะที่ระบบทำนาย Precision = TP/(TP+FP), Recall = TP/(TP+FN), F1 = 2PR/(P+R) เมื่อไม่มีตัวหารระบบคืน 0 ชื่อทักษะต้องสอดคล้องกันเพื่อไม่ให้เทียบผิด

## 9 อัลกอริทึมและโมเดลที่ใช้

### TF IDF และพจนานุกรมทักษะ

ระบบปรับข้อความด้วย Unicode NFKC และแปลงเป็นตัวพิมพ์เล็ก สร้างหน่วยคำภาษาอังกฤษด้วยรูปแบบตัวอักษรและตัวเลข ส่วนภาษาไทยใช้ช่วงตัวอักษรยาว 3 ตัวต่อเนื่อง ไม่ได้ใช้ตัวตัดคำไทย จากนั้นสร้าง TF-IDF และคำนวณ cosine similarity

การหา Required skills ตรวจคำใน Role Brief กับพจนานุกรม 18 หมวด แล้วจึงหาคำหรือชื่อเรียกใน Resume เช่น Git มี GitHub และ GitLab เป็นชื่อที่รับรู้ การจับภาษาอังกฤษตรวจขอบคำเพื่อลดการพบคำบางส่วนผิดตำแหน่ง

ทักษะที่รองรับคือ Python, FastAPI, SQL, Git, REST API, JavaScript, TypeScript, React, Next.js, Docker, Excel, Power BI, Figma, User Research, Machine Learning, YOLO, Teamwork และ Communication

### MiniLM และหลักฐานเชิงความหมาย

Proposed ใช้ sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2 แปลงข้อความเป็นเวกเตอร์ที่ปรับความยาวแล้ว แบ่ง Resume เป็นช่วง 220 ตัวอักษรซ้อนทับกัน 40 ตัว แล้วหาแต่ละทักษะว่าคล้ายกับช่วงใดมากที่สุด

ถ้าผ่านเกณฑ์ 0.55 อาจแสดงเป็นหลักฐานที่พบโดยความหมาย แต่ยังเป็นรายการที่เป็นไปได้ให้คนตรวจ ไม่ใช่การรับรองทักษะ และยังเริ่มจากทักษะในพจนานุกรมของ JD จึงไม่ได้ค้นทุกทักษะที่เป็นไปได้อย่างอิสระ

### RAG สำหรับ FAQ

Chroma เก็บเวกเตอร์ FAQ แต่ละชุดใน Collection ตามลายเซ็นข้อมูล เมื่อฐานเปลี่ยนจะใช้ Collection ของชุดปัจจุบัน การค้นคืนช่วยจำกัดข้อมูลให้ Qwen3 ก่อนสร้างคำตอบ ลดการตอบนอกเอกสาร แต่ไม่ทำให้คำตอบถูกต้องแน่นอน

### Qwen3 ผ่าน Ollama

Ollama เป็นตัวให้บริการโมเดลในเครื่อง ส่วน Qwen3 เป็นโมเดลที่สร้างข้อความ Backend เรียก /api/chat ตั้ง think เป็น false, stream เป็น false, temperature เป็น 0 และขอผลตาม JSON Schema

ตัวอ่านผลยอมรับ JSON ปกติหรือ JSON หลังส่วน reasoning ที่ปิดแล้ว และตรวจชนิดข้อมูลซ้ำด้วย Pydantic หากโมเดลส่งรูปแบบผิด อ้างหลักฐานไม่ครบ หรือผลถูกตัด จะรายงานปัญหา ไม่ควรแก้โดยตัดข้อความหลังเครื่องหมายแบบไม่ตรวจโครงสร้าง

## 10 ข้อมูล การตั้งค่า และการส่งต่อ

### ที่เก็บข้อมูล

ค่าเริ่มต้นใช้ backend/runtime/coopready.sqlite3 ตาราง records เก็บชนิดข้อมูลและ payload แบบ JSON ประกอบด้วย Session, FAQ และประวัติถาม FAQ ส่วน Chroma ใช้โฟลเดอร์ runtime/chroma โมเดลและแคชบางชนิดอาจอยู่ในพื้นที่ของไลบรารีหรือ Ollama นอกโฟลเดอร์โปรเจกต์

## 11 ผลทดสอบและการประเมินโครงงาน

### ผลตรวจซอฟต์แวร์ที่บันทึกไว้

- Backend และตัวเปิดมี pytest ผ่าน 57 รายการ บน Linux และ Python 3.12

- Frontend มี Node regression tests ผ่าน 7 รายการ และ Next.js production build ผ่าน

- HTTP smoke เปิด Next และ FastAPI จริง ทดสอบอัปโหลด TXT บันทึก Session วิเคราะห์ สัมภาษณ์ Baseline 5 รอบ และ Proposed 7 รอบ รายงาน FAQ และส่งออก

- การทดสอบ Proposed ในชุดดังกล่าวใช้ Ollama จำลองแบบควบคุมได้ ไม่ใช่ผลของ Qwen3 จริง

- เคยทดสอบเส้นทางโมเดลตอบช้า 31 วินาที และแตกโครงงานในพาธมีภาษาไทยกับช่องว่างบน Linux

### สิ่งที่ยังต้องทดสอบจริง

ยังไม่มีผลยืนยันครบชุดสำหรับ Qwen3, MiniLM/Chroma, faster-whisper และ Piper ด้วยข้อมูลจริงบนเครื่องผู้ใช้ ยังไม่ได้ทดสอบคลิกทุกปุ่มและไมโครโฟนในเบราว์เซอร์ครบ หรือรันทั้งโครงการบน Windows และ macOS จริง ผล build และ HTTP ไม่ทดแทนการทดสอบเหล่านี้

ชุดตัวอย่าง Resume 3 คู่ให้ micro Precision 1.00, Recall 0.80 และ F1 ประมาณ 0.8889 เป็นข้อมูลสมมติขนาดเล็ก ใช้ตรวจการคำนวณและอธิบาย Baseline ได้ แต่ยังใช้สรุปความแม่นยำกับนักศึกษาจริงไม่ได้

### วิธีเก็บผลเพื่อนำเสนอ

ใช้ Resume กับ Role Brief ชุดเดียวกันทดสอบสองโหมด แยกข้อมูลที่ใช้พัฒนาหรือปรับเกณฑ์ออกจากชุดประเมิน ให้คนตรวจทักษะจริงและหลักฐานเป็น Ground truth แล้วรายงาน Precision, Recall และ F1 พร้อมจำนวนตัวอย่างและข้อผิดพลาด

ด้านสัมภาษณ์ให้ผู้ประเมินอย่างน้อยสองคนตรวจความตรงบริบท หลักฐาน คำถามต่อยอด และความสอดคล้องกับ Rubric ด้าน FAQ เก็บทั้งคำถามที่มีคำตอบและไม่มีคำตอบ วัดคำตอบถูกต้อง การงดตอบ และการอ้างเอกสาร ส่วนเสียงใช้ข้อความอ้างอิงที่คนตรวจแล้วคำนวณ CER

### ความสัมพันธ์กับสิ่งที่ต้องนำเสนอ

มีโค้ด Baseline ที่รันได้และผลเริ่มต้นสำหรับสาธิต รวมทั้งแนวทาง Proposed แต่การยืนยันว่าตรงสไลด์ทั้งหมดต้องตรวจสไลด์ฉบับที่จะส่งอีกครั้ง โดยเฉพาะชื่อโมเดล จำนวนตัวอย่าง ตัวชี้วัด และฟังก์ชันที่ยังเป็นแผน ห้ามนำผลทดสอบโปรแกรมไปอ้างเป็นความแม่นยำ AI

__init__ สร้างพื้นที่และตาราง • connect เปิด SQLite • put เพิ่มหรือแทนที่ข้อมูลพร้อมเวลาแก้ไข • get อ่านตาม ID และชนิด • list เรียงรายการล่าสุด • delete ลบตาม ID • purge ลบรายการหมดอายุและเสียงชั่วคราวเก่า • session_lock ล็อกงานต่อ Session ด้วย RLock

## เพิ่มเติม วิธีเปิดบน Windows และ Linux

### Windows ใน Terminal ของ VS Code

เปิดโฟลเดอร์ที่มี `launch.py` แล้วรัน:

```powershell
python launch.py
```

หากขึ้น `can't open file ... launch.py` หรือ `No such file or directory` ให้ค้นหาไฟล์ในโฟลเดอร์ที่แตก ZIP แล้วเข้าโฟลเดอร์ให้ถูกต้อง:

```powershell
$coopLaunch = Get-ChildItem -Path . -Filter launch.py -Recurse -File | Select-Object -First 1
if ($coopLaunch) {
    Set-Location $coopLaunch.DirectoryName
    Get-Location
} else {
    Write-Host "ไม่พบ launch.py ให้แตกไฟล์ ZIP ฉบับเต็มก่อน"
}
```

เมื่อพบแล้วจึงรัน `python launch.py` อีกครั้ง ถ้ามี Python Launcher สามารถใช้ `py -3.12 launch.py` แทนได้

ติดตั้งความสามารถด้านความหมายและถอดเสียง:

```powershell
python launch.py --install-ai semantic stt --prepare-models semantic stt
python launch.py
```

คำสั่งติดตั้งจะจบเมื่อเตรียมเสร็จ ต้องรันตัวเปิดอีกครั้งเพื่อเปิดเว็บ

### Linux

ต้องมี Python 3.11 หรือ 3.12, โมดูล venv ของ Python รุ่นนั้น และ Node.js 22 ขึ้นไป ตรวจด้วย:

```bash
python3 --version
node --version
```

เข้าโฟลเดอร์ที่มี `launch.py` แล้วรัน:

```bash
python3 launch.py
```

หาก `python3` เป็นรุ่นที่ระบบไม่รองรับ ให้ใช้ตัวแปลรุ่นที่ติดตั้งไว้ เช่น:

```bash
python3.12 launch.py
```

ถ้าต้องการเปิดโดยไม่เรียกเบราว์เซอร์อัตโนมัติ:

```bash
python3 launch.py --no-browser
```

ตัวเปิดผูกบริการกับ `127.0.0.1` จึงเปิดได้จากเครื่องเดียวกันโดยค่าเริ่มต้น การรันบนเซิร์ฟเวอร์ระยะไกลต้องจัดการช่องทางเข้าถึงเพิ่มเติม `--no-browser` เพียงอย่างเดียวไม่ได้เปิดให้เครื่องอื่นเข้าถึง

เมื่อย้ายจาก Windows มา Linux ให้ติดตั้งแพ็กเกจใหม่ ไม่คัดลอก `.venv`, `node_modules` หรือ `.next` ข้ามระบบปฏิบัติการ ต้องติดตั้ง Ollama และจัดเตรียมโมเดลกับเสียง Piper บนเครื่องปลายทางแยกต่างหาก
